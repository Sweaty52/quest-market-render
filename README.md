# Telegram AI Inbox

Особистий Telegram AI Inbox для одного або кількох власників. Керувальний бот на aiogram і клієнт особистого акаунта на Telethon працюють як окремі компоненти. BotFather-бот не читає особисті чати: для цього власник окремо авторизує Telethon-сесію.

## Архітектура

- `bot/handlers.py` — головне меню, статистика й журнал рішень.
- `bot/inbox_handlers.py` — вхідні, AI Inbox, чернетки, пошук, підтверджене надсилання.
- `bot/contact_handlers.py` — налаштування окремих чатів, дозволи, пауза й архів.
- `bot/rules_handlers.py` — правила за контактом, категорією та текстовою умовою.
- `bot/control_handlers.py` — автоматизація, стиль, приватність і Telegram-сесія.
- `bot/telegram_client.py` — Telethon-клієнт, черга подій, синхронізація ручних відповідей і перевірка доставки.
- `bot/service.py`, `bot/policy.py` — обробка повідомлень та fail-closed політика.
- `bot/ai.py`, `bot/analyzer.py` — OpenAI Responses API, структурований аналіз і генерація чернеток.
- `bot/db.py`, `bot/migrations/` — асинхронний доступ до PostgreSQL та версійні SQL-міграції.

Усі налаштування зберігаються в PostgreSQL. Вхідні події обробляються через обмежену чергу. Повідомлення мають ідемпотентні ключі, а повторне натискання на надсилання не створює другу відправку. Якщо відповідь могла дійти, але мережа не підтвердила результат, чернетка переходить у стан «невідомо»; перед повтором бот перевіряє історію Telegram.

## Вимоги

- Python 3.12 або Docker із Docker Compose.
- Telegram-бот, створений через BotFather, та числовий Telegram ID власника.
- PostgreSQL 16+.
- Для читання особистих чатів: `API ID` і `API Hash` із [my.telegram.org/apps](https://my.telegram.org/apps).
- Для AI-функцій: OpenAI API key із доступом до вибраної моделі.

## Конфігурація

Скопіюйте шаблон та заповніть локальний `.env`:

```sh
cp .env.example .env
```

Потрібні змінні:

```dotenv
BOT_TOKEN=                 # BotFather
OWNER_IDS=123456789        # лише ваш числовий Telegram ID
DATABASE_URL=postgresql://message_control:password@localhost:5432/message_control
OPENAI_API_KEY=            # необов’язково; без ключа Inbox працює без AI
OPENAI_MODEL=gpt-4.1-mini
TELEGRAM_API_ID=           # my.telegram.org/apps
TELEGRAM_API_HASH=
TELETHON_SESSION_PATH=./data/telegram_account
```

Не додавайте `.env` або файл `*.session` до Git і не надсилайте їх у Telegram. Приклад `.env.example` містить лише порожні значення або демонстраційні паролі.

## Локальний запуск

1. Створіть базу PostgreSQL і вкажіть робочий `DATABASE_URL` у `.env`. Для локального PostgreSQL на macOS:

   ```sh
   brew services start postgresql@16
   createuser -P message_control
   createdb -O message_control message_control
   ```

   Вкажіть створений пароль у `DATABASE_URL` у форматі `postgresql://message_control:ВАШ_ПАРОЛЬ@localhost:5432/message_control`.

2. Встановіть залежності й запустіть контрольний бот:

   ```sh
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install -e '.[dev]'
   python -m bot.main
   ```

3. Відкрийте бота в Telegram і натисніть `/start`. Перша схема бази застосовується автоматично.

## Авторизація особистого акаунта

1. Створіть застосунок на `my.telegram.org/apps`, додайте `TELEGRAM_API_ID` і `TELEGRAM_API_HASH` у локальний `.env`.
2. У локальному терміналі запустіть:

   ```sh
   python -m bot.auth --owner-id 123456789
   ```

3. Введіть номер телефону, код Telegram і, якщо попросять, пароль двоетапної перевірки в терміналі.
4. Запустіть `python -m bot.main`. Стан акаунта та автоматизацію надалі контролюйте в боті: **Налаштування → Особистий Telegram**.

Код входу й пароль 2FA не вводяться в керувальний бот. Файл Telethon-сесії — це авторизація акаунта: збережіть його приватно. Кнопка «Вимкнути автоматизацію» зупиняє обробку, але залишає локальну сесію. Кнопка «Завершити сесію» просить Telegram відкликати авторизацію й лише після підтвердження видаляє файл.

Для кількох власників вкажіть усі ID через кому в `OWNER_IDS`. Для кожного власника команда авторизації створить окремий файл сесії.

## Режими та контроль

- **Ручний** — Inbox зберігає та показує повідомлення й аналіз, але не створює відповіді автоматично.
- **AI Assist** — пропонує чернетки лише для контактів із дозволом AI.
- **Auto Reply** вимкнений за замовчуванням. Його потрібно підтвердити глобально й окремо для кожного чату.
- Глобальна зупинка блокує відправлення. Фінансові, юридичні, конфіденційні, конфліктні та інші чутливі повідомлення, низька впевненість і недостатній контекст передаються власнику.
- Кожна чернетка перед ручним надсиланням показує контакт і чат для підтвердження. Перед відправкою бот повторно перевіряє, що чат не змінився і власник ще не відповів.
- Фото й інші вкладення позначаються в Inbox, але вміст вкладення не завантажується та не аналізується.

Повідомлення й контекст передаються OpenAI для аналізу та генерації лише за наявності ключа й увімкненого AI. Приклади стилю є контекстом запиту й не використовуються застосунком для навчання моделі. У **Налаштування → Приватність** можна змінити строк зберігання або видалити збережені повідомлення та журнал.

## Docker Compose

Заповніть `.env`, зокрема `BOT_TOKEN`, `OWNER_IDS` і власний `POSTGRES_PASSWORD`, потім:

```sh
docker compose up -d --build
```

Авторизація особистого акаунта в контейнері:

```sh
docker compose run --rm app python -m bot.auth --owner-id 123456789
docker compose restart app
```

Compose зберігає базу в `postgres_data`, а Telethon-сесії — у `inbox_data`. Для локального запуску без Docker команда авторизації використовує шлях із `TELETHON_SESSION_PATH`.

## Тести

Звичайний набір не звертається до Telegram або OpenAI і не потребує секретів:

```sh
pytest -q
```

Щоб запустити інтеграційні тести PostgreSQL, задайте окрему тимчасову базу через `TEST_DATABASE_URL`. Тести створюють і видаляють лише записи тестового власника в цій базі.

## Резервна копія та відновлення

Для Docker:

```sh
mkdir -p data/backups
docker compose exec -T postgres pg_dump -U message_control -d message_control -Fc > data/backups/message_control.dump
docker compose exec -T postgres pg_restore -U message_control -d message_control --clean --if-exists < data/backups/message_control.dump
```

Для локального PostgreSQL використовуйте `pg_dump -Fc` та `pg_restore` із параметрами вашого сервера. Зберігайте резервні копії зашифрованими; вони містять приватні повідомлення.

## Діагностика

- **PostgreSQL недоступний** — перевірте, чи запущений сервер і чи відповідає `DATABASE_URL` способу запуску (локальний сервер або Compose).
- **Telegram-акаунт не підключено** — перевірте `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` і відповідний файл сесії; повторну авторизацію виконайте через `bot.auth`.
- **AI не створює чернетки** — перевірте `OPENAI_API_KEY`, `OPENAI_MODEL`, ліміт API та дозвіл AI для контакту.
- **Чернетка має стан «невідомо»** — натисніть «Перевірити доставку». Бот перевірить історію Telegram і не повторить відправлення без підтвердження.
- **FloodWait / обмеження Telegram** — дочекайтеся вказаного Telegram часу; не запускайте повторну масову відправку.

## Quest Market

Quest Market працює як окремий бот і не замінює Inbox. Для нього потрібен окремий BotFather-токен, оскільки один Telegram-бот не може одночасно обслуговувати два процеси polling.

1. Створіть бота через `@BotFather` і додайте його токен до локального `.env` як `MARKET_BOT_TOKEN`.
2. У `@BotFather` виконайте `/setinline` для бота Quest Market, щоб увімкнути інлайн-режим.
3. Додайте до `.env` `MARKET_ACCOUNT_URL=tg://send_gift?to=questbankk`. Це посилання вже встановлене як типовий варіант.
4. Задайте публічний HTTPS URL вебапки у `WEBAPP_URL`.
5. Обмежте доступ лише до inline-результатів: задайте у `.env` `MARKET_ALLOWED_USER_IDS=123456789,987654321` (вкажіть Telegram ID людей, яким дозволено публікувати офери через inline). За замовчуванням список порожній і inline-результати нікому не видаються. Користувач може дізнатися свій ID командою `/myid`.
6. Запустіть Quest Market:

   ```sh
   python -m bot.market_main
   ```

Quest Market не підключається до PostgreSQL. Офери зберігаються в пам'яті процесу й очищаються після його зупинки або перезапуску. PostgreSQL сервіс у Compose залишається окремою залежністю Inbox-застосунку.

Для Render у корені є `render.yaml`: створіть Blueprint із приватного Git-репозиторію й додайте `MARKET_BOT_TOKEN` та `MARKET_ALLOWED_USER_IDS` як секретні змінні в Dashboard. Blueprint запускає вебсервіс у webhook-режимі та бере URL Mini App з `RENDER_EXTERNAL_URL`. На безкоштовному тарифі Render засинає після 15 хвилин без вхідного трафіку й може прокидатися близько хвилини; перший Telegram update після сну може затриматися. Стан оферів у пам'яті скидається після перезапуску.

У приватному чаті з Quest Market створіть офер короткою командою `.buy https://t.me/nft/... 12.5 grams` або `.buy https://t.me/nft/... 500 stars`. Для Stars приймається ціле число. Бот видасть кнопку `Copy inline`; вставте скопійований запит у поле повідомлення потрібного чату та виберіть inline-результат Telegram, щоб надіслати картку з кнопками.

Після `/start` користувачі з allowlist отримують привітання з інструкціями для GRAM і Stars, без кнопки відкриття вебапки. Решта користувачів отримує кнопку `Open Quest Market`. Каталог, `.buy`, довідка та кнопки оферів доступні всім; список ID перевіряється лише під час запиту inline-результату.

Після прийняття офера продавцю показуються кнопки `Transfer gift`, `I've transferred` і `How it works`. Передача позначається самим користувачем і не є автоматичною перевіркою блокчейну чи оплатою; статус у боті позначається як такий, що очікує перевірки маркетом.

Вітрина містить 120 юзернеймів, 120 номерів `+888` і 129 подарунків із наданих NFT-посилань. Каталог підтримує пошук, сортування й фільтр колекцій; картки подарунків ведуть на Telegram NFT та в бот для створення офера. Ціни каталогу відображаються в GRAM; у приватному офері можна вибрати GRAM або Stars. Зображення подарунків завантажуються з публічних прев’ю наданих Telegram NFT-посилань.

Щоб повністю зупинити застосунок, натисніть `Ctrl+C` або виконайте `docker compose down`. Щоб відкликати доступ особистого акаунта, скористайтеся кнопкою завершення сесії в боті або завершіть сесію в офіційному Telegram-клієнті.
